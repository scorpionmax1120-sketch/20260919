# 05 · 程式出錯時怎麼問

## ❌ 沒救的問法

> 不能跑
> 有錯誤
> 還是不行

它只能用猜的，然後給你另一個猜測。你們會來回五次都修不好。

---

## ✓ 一次就解決的模板

```
我執行了這個指令：
（貼上你打的完整指令）

出現這個錯誤：
（貼上完整的錯誤訊息，包含整段 Traceback，不要只貼最後一行）

我的環境：
- Python 3.12
- FastAPI 0.115
- macOS / Windows 11

相關的程式碼：
（貼上出錯的那個檔案）

我期待的結果是：
（例如：回傳 200 和一個 token）

請先說明這個錯誤的原因，再給修正後的程式碼。
```

---

## 為什麼要加最後那句

**「請先說明原因，再給程式碼」** —— 先解釋，你才學得到東西。

否則你只是拿到另一段看不懂的程式碼，下次遇到同樣的錯還是不會修。

---

## 四樣東西缺一不可

| | 為什麼 |
| --- | --- |
| ① 你執行的完整指令 | 很多錯誤來自指令本身打錯 |
| ② 完整錯誤訊息（含 Traceback） | 最後一行常常不是真正的原因 |
| ③ 環境（版本、作業系統） | 同樣的程式碼在不同版本行為不同 |
| ④ 你期待的結果 | 否則它不知道什麼叫「修好了」 |

---

## 除錯的順序

1. 瀏覽器 **Console**（F12）—— 前端的錯
2. 瀏覽器 **Network** —— 請求真的送出去了嗎？標頭對嗎？狀態碼幾號？
3. **後端終端機** —— uvicorn 的紅字

**不要用猜的。** 先看狀態碼：4xx 是你（前端）錯了，5xx 是後端錯了。

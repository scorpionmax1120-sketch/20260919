# 07 · 練習：自己加一支 API

## 任務

新增 **`POST /api/profile`**，讓登入者可以修改自己的 `dept` 欄位。

## 規格（你要自己寫成提示詞）

- 必須帶有效 token 才能改，沒帶或無效回 401
- 只能改 token 對應到的那個人，**不能改別人的資料**
- 輸入：`{"dept": "新的系所"}`
- 成功回 200 和更新後的完整個人資料

## 評分標準

- [ ] 用四段式骨架寫提示詞（角色 / 目標 / 規格 / 限制 / 輸出）
- [ ] 產出後能**指出哪一行在驗證 token**
- [ ] 自己測過「沒帶 token」的情況
- [ ] 自己測過「帶 A 的 token 想改 B 的資料」

## 進階挑戰

1. 先故意寫一段**含糊的**提示詞（例如「幫我加一個修改個人資料的功能」），看它給你什麼
2. 再把它改精確
3. **比較兩次的差別** —— 這是這個練習真正要你體會的事

## 提示

第三個評分標準是陷阱。很多人寫出來的版本會讓使用者自己傳 `username`，變成「誰都能改任何人的資料」。

正確做法是：**username 只能從 token 推導出來，絕對不能從請求的 body 拿。**

這就是為什麼你需要懂 —— AI 不會替你想這件事，除非你在「限制」裡寫出來。

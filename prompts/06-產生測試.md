# 06 · 用 AI 產生測試

對應簡報 Topic 06、demo 的 `step-7-tests`。

---

## 完整提示詞

```
你是熟悉 pytest 的 Python 測試工程師。

目標：為下面這支 /api/login 寫 pytest 測試。
（把你的 main.py 貼上來）

請涵蓋這些情境：
- 帳號密碼正確 → 200 且回應有 token
- 密碼錯誤 → 401
- 帳號不存在 → 401
- 缺少 password 欄位 → 422
- username 是空字串
- password 是 1000 個字元的超長字串
- username 傳入 SQL 注入字串 ' OR '1'='1

限制：
- 用 fastapi.testclient.TestClient
- 一個情境一個測試函式，函式名要看得懂
- 每個測試加繁體中文註解說明在測什麼

最後：請另外列出你想到、但我沒列到的測試案例。
```

**最後那一行是重點。** 它會把 AI 從打字機變成同事。

---

## 它通常會補上你沒想到的

- 大小寫不同的帳號算同一個嗎
- 前後有空白的帳號
- Unicode、表情符號當密碼
- 同一組帳密連續登入，token 會不會重複
- 錯誤訊息有沒有洩漏「帳號存在」

這就是 AI 在測試上的真正價值：它不會累，也沒有「應該不會有人這樣用」的盲點。

## 執行

```bash
pip install pytest httpx
pytest -v
```

不需要先啟動 uvicorn —— `TestClient` 是一個假的瀏覽器，會直接把請求送進 app。

## 一個真實踩到的坑

`demo/step-7-tests` 裡有一個註解特別標出來的地方：

```python
# ✗ 會拋 UnicodeEncodeError，測到的不是 401
headers={"Authorization": "Bearer 隨便亂打的"}

# ✓ HTTP 標頭只能放 ASCII
headers={"Authorization": "Bearer not-a-real-token"}
```

**HTTP 標頭不能放中文。** AI 產生測試時很容易寫出上面那種，因為它看起來很合理 —— 這就是為什麼你要自己跑一次。

---

## 請 AI 修 bug 的正確順序

1. **先寫測試**，讓失敗可以被重現
2. 貼完整訊息：測試碼 + 失敗輸出 + 相關程式碼
3. 要它**先解釋**為什麼會錯
4. **再跑一次測試**，綠了才算修好

沒有第 1 步，你永遠不知道它到底修好了沒。「看起來好了」不是驗收標準。

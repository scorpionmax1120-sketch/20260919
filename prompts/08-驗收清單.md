# 08 · 貼上之前先檢查

## 三個必問

在按下貼上之前，先問自己：

1. **這段程式碼，哪一行在做驗證？**
   指得出來，代表你看懂了流程；指不出來，先叫它逐行解釋。

2. **如果使用者送出空密碼、超長字串，會發生什麼事？**
   AI 很常忽略邊界情況 —— 這是它最典型的疏漏。

3. **它有沒有回傳不該回傳的東西？**
   密碼、內部錯誤訊息、其他人的資料，都是常見的外洩來源。

**三題都答得出來，才按下貼上。**

---

## AI 最常出的四種錯

| | 症狀 | 怎麼驗證 |
| --- | --- | --- |
| **幻覺** | 發明不存在的套件、函式、參數，而且講得非常有自信 | 直接去官方文件搜尋那個名字 |
| **過時** | 用三年前的寫法，能跑但已被官方淘汰 | 問「這是目前的建議寫法嗎？」 |
| **不安全的預設** | `allow_origins=["*"]`、密碼明文存、debug 開著上線 | 對照下面的清單 |
| **過度設計** | 你只要一支 API，它給你一套架構 | 看不懂就是不能用，要求它簡化 |

---

## 上線前的資安清單

- [ ] `allow_origins` 沒有留著 `"*"`
- [ ] 密碼有雜湊（`bcrypt` / `argon2`），不是明文
- [ ] API 回應裡沒有 `password` 欄位
- [ ] 錯誤訊息不區分「帳號不存在」和「密碼錯誤」
- [ ] SQL 全部用 `?` 參數化，沒有字串相加
- [ ] `.env`、`*.db`、`.venv/` 都在 `.gitignore` 裡
- [ ] GitHub 的 commit 紀錄裡沒有金鑰或密碼
- [ ] debug 模式沒有開著上線

> GitHub 上的秘密會被機器人在幾分鐘內掃到。
> 已經推上去的話，**改密碼比刪 commit 重要得多**。

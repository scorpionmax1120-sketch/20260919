用 AI 一步步做出同樣的成果

把上午的每個 Step，改寫成一段提示詞。

PART 3 · 70 MIN
模板

一段好提示詞的四個部分

01 角色你是誰「你是資深 Python 後端工程師」

決定它用什麼水準、什麼慣例回答你
02 目標要什麼「寫一支登入 API」

一次一個目標，不要包裹三件事
03 限制不要什麼「不要用 JWT」「先不接資料庫」

這一欄最常被省略，也最關鍵
04 輸出長什麼樣「完整的 main.py 加啟動指令」

講清楚你要拿到什麼形式
少了第 03 欄，你會拿到一個「很厲害但你看不懂」的版本。
對照

同一個需求，兩種問法

❌ 你會拿到災難「幫我做一個登入系統」它會給你：JWT、SQLAlchemy、Alembic、Docker、OAuth2……一個你完全看不懂也跑不起來的專案。

然後你連從哪裡開始除錯都不知道。
✓ 你會拿到能用的「用 FastAPI 寫一支 POST /api/login，輸入 username 和 password，成功回 token，失敗回 401，資料先用 dict 假資料，不要用 JWT」它會給你一個你看得懂、跑得動、改得動的版本。
差別不在 AI 有多強，在你把需求講得多清楚。這件事跟你將來帶人做專案一模一樣。
兩條鐵則

用 AI 寫程式的紀律

鐵則一一次只要一步寫一支 API → 跑起來 → 確認對 → 再問下一步。

一次要五個功能，五個都有小問題，你會分不清是哪裡壞的。
鐵則二給規格，不要給願望「做個好用的登入」是願望。
「POST /api/login，成功 200 回 token，失敗 401」是規格。

上午寫過規格表，現在直接貼給它。
注意到了嗎？你上午學的每一件事，現在都變成了跟 AI 溝通的詞彙。
重做 Step 1

第一個伺服器

你是 Python 教學者，對象是第一次寫後端的大學生。 目標：用 Python 標準函式庫（不要裝任何套件）寫一個 最簡單的 HTTP 伺服器，聽在 127.0.0.1:8000， 任何 GET 請求都回傳純文字「我是伺服器」。 限制： - 不要用 Flask 或 FastAPI - 程式碼不超過 15 行 - 每一行都要有繁體中文註解，解釋它在做什麼 輸出：完整可執行的 main.py，以及啟動指令。
對照一下：它給你的，跟你上午手寫的那 12 行，幾乎一樣。因為你上午就是對的。
重做 Step 5

登入 API 的完整提示詞

你是資深 Python 後端工程師。 目標：用 FastAPI 寫一支登入 API。 規格： - POST /api/login - 輸入 JSON：username、password - 成功回 200，body 是 {"token": "隨機字串"} - 失敗回 401，detail 是「帳號或密碼錯誤」 - 帳號不存在和密碼錯誤，都回同一個訊息 - token 用 secrets.token_hex(16) 產生，存在記憶體的 dict 限制： - 只寫這一支 API，不要順便加別的功能 - 不要用 JWT、不要接資料庫，我還沒學 - 不要寫 try/except 包住全部 - 每段加繁體中文註解 輸出：完整的 main.py，以及測試用的 curl 指令。

手寫版 vs AI 版

當它寫錯時

怎麼回報錯誤

❌ 沒救的問法「不能跑」
「有錯誤」
「還是不行」它只能用猜的，然後給你另一個猜測。你們會來回五次都修不好。
✓ 一次就解決四樣東西一起給① 你執行的完整指令
② 完整的錯誤訊息（含 Traceback）
③ 你的環境（Python 版本、作業系統）
④ 你期待的結果
加一句非常有效的話：「請先說明這個錯誤的原因，再給修正後的程式碼。」先解釋，你才學得到東西。
貼上之前

先問自己三個問題

  • 這段程式碼，哪一行在做驗證？指得出來，代表你看懂了流程；指不出來，先問 AI 逐行解釋
  • 如果使用者送出空密碼、超長字串，會發生什麼事？AI 很常忽略邊界情況 —— 這是它最典型的疏漏
  • 它有沒有回傳不該回傳的東西？密碼、內部錯誤訊息、其他人的資料，都是常見的外洩來源
三題都答得出來，才按下貼上。這個習慣會跟著你整個職涯。
已知地雷

AI 最常出的四種錯

01 幻覺發明不存在的東西套件名、函式名、參數，講得非常有自信但根本沒有。
驗證：直接去官方文件搜尋。
02 過時用的是三年前的寫法能跑，但已經被官方標記淘汰。
驗證：問「這是目前的建議寫法嗎？」
03 不安全的預設圖方便的設定allow_origins=["*"]、密碼明文存、debug 模式開著上線。
04 過度設計給你用不到的複雜度你只要一支 API，它給你一套架構。看不懂就是不能用。

06

用 AI 進行測試

最無聊的工作，剛好是 AI 最擅長的。

PART 3 · 30 MIN
為什麼

沒有測試的專案，改一行就要全部重試

沒有測試每次改動都要手動點一遍開瀏覽器 → 登入 → 看畫面 → 登出 → 試錯密碼……

改五次就點五遍。所以大家最後都不點了，然後上線才爆炸。
有測試一行指令，兩秒知道pytest

七個情境全部自動跑一遍，哪個壞了直接告訴你。
測試不是為了證明程式對，是為了讓你敢改。這跟上午 Git 分支的道理完全一樣。
分類

測試的三個層次

UNIT單元測試測一個函式
快、多、便宜
▶
API介面測試測一支 API 的輸入輸出

今天做這層
▶
E2E端對端測試模擬真人操作瀏覽器
慢、貴、但最接近真實
為什麼選中間？對後端來說，API 測試的投報率最高 —— 一個測試就涵蓋了路由、驗證、邏輯、回應格式。
提示詞

叫 AI 寫測試

你是熟悉 pytest 的 Python 測試工程師。 目標：為下面這支 /api/login 寫 pytest 測試。 （把你的 main.py 貼上來） 請涵蓋這些情境： - 帳號密碼正確 → 200 且回應有 token - 密碼錯誤 → 401 - 帳號不存在 → 401 - 缺少 password 欄位 → 422 - username 是空字串 - password 是 1000 個字元的超長字串 - username 傳入 SQL 注入字串 ' OR '1'='1 限制： - 用 fastapi.testclient.TestClient - 一個情境一個測試函式，函式名要看得懂 - 每個測試加繁體中文註解說明在測什麼 最後：請另外列出你想到、但我沒列到的測試案例。
看懂它

pytest 的長相

from fastapi.testclient import TestClient from main import app client = TestClient(app) # 一個假的瀏覽器，不用真的開伺服器 def test_login_success(): # 函式名一定要 test_ 開頭 """正確的帳號密碼應該拿到 token""" r = client.post("/api/login", json={"username": "jase", "password": "1234"}) assert r.status_code == 200 # assert = 我主張…… assert "token" in r.json() # 不成立就算這個測試失敗 def test_login_wrong_password(): """密碼錯誤應該被擋下來""" r = client.post("/api/login", json={"username": "jase", "password": "xxxx"}) assert r.status_code == 401
執行：pip install pytest 然後 pytest -v。綠色是通過，紅色是失敗。
驚喜

AI 想到的，通常比你多

你會想到的
  • 帳號密碼對
  • 密碼錯
  • 帳號不存在
它還會補上的
  • 大小寫不同的帳號算同一個嗎
  • 前後有空白的帳號
  • Unicode、表情符號當密碼
  • 同一組帳密連續登入，token 會不會重複
  • 錯誤訊息有沒有洩漏「帳號存在」
這就是 AI 在測試上的真正價值：它不會累，也沒有「應該不會有人這樣用」的盲點。
紅燈

看懂失敗訊息

FAILED test_main.py::test_login_wrong_password def test_login_wrong_password(): r = client.post("/api/login", json={...}) > assert r.status_code == 401 E assert 403 == 401 E + where 403 = <Response [403]>.status_code ══ 1 failed, 6 passed in 0.42s ══
  • 哪個測試失敗了：test_login_wrong_password
  • 期待什麼、實際拿到什麼：期待 401，實際 403
  • 其他六個還是綠的 —— 所以問題被縮小到一個地方了
流程

請 AI 修 bug 的正確順序

01先寫測試讓失敗可以被重現
▶
02貼完整訊息測試碼＋失敗輸出＋相關程式碼
▶
03要它先解釋「為什麼會 403」
▶
04再跑一次綠了才算修好
沒有第 01 步，你永遠不知道它到底修好了沒。「看起來好了」不是驗收標準，測試變綠才是。
數字的陷阱

測試覆蓋率

它告訴你什麼哪幾行從來沒被跑過pytest --cov 會列出沒被測試碰到的行數。

那些地方是你的盲區。
它不告訴你什麼跑過 ≠ 測對了每一行都跑過，但你只檢查了「有回應」沒檢查「回應正確」—— 覆蓋率一樣是 100%。
把它當地圖，不要當成績。覆蓋率低一定有問題，覆蓋率高不代表沒問題。

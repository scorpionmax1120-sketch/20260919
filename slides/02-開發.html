STEP 1 — 伺服器到底是什麼

最原始的伺服器：它只是在「聽」

# main.py — 完全不用任何套件，Python 內建就有 from http.server import HTTPServer, BaseHTTPRequestHandler class Handler(BaseHTTPRequestHandler): def do_GET(self): # 有人用 GET 來敲門時執行這裡 self.send_response(200) self.send_header("Content-Type", "text/plain; charset=utf-8") self.end_headers() self.wfile.write("我是伺服器，我聽到你了".encode("utf-8")) print("聽在 http://127.0.0.1:8000") HTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
執行：python3 main.py —— 然後注意，它不會結束。這就是伺服器：一個永遠不結束、一直在等的程式。
CONCEPT — Port 是什麼

一台機器，很多扇門

  • IP 位址 = 這棟大樓的地址127.0.0.1 就是「我自己這台」
  • Port = 大樓裡的門牌號碼0–65535，一個程式佔一個
  • 同一個 port 只能有一個程式在聽這就是 Address already in use 的原因
Port慣例用途
80HTTP（網站預設）
443HTTPS（加密網站）
3306MySQL 資料庫
8000開發用，我們今天用這個
遇到 Address already in use？代表上一個伺服器還活著。回去那個終端機按 Ctrl + C 把它關掉。

STEP 5 — 先設計，再動手

登入 API 的規格

項目內容
路徑POST /api/login
輸入{ "username": "jase", "password": "1234" }
成功200 · { "token": "一串隨機字串" }
失敗401 · { "detail": "帳號或密碼錯誤" }
不能做回傳密碼、回傳「帳號不存在」或「密碼錯誤」的區別
最後一行是資安慣例。分開告知等於幫攻擊者確認哪些帳號存在。兩種情況都只說「帳號或密碼錯誤」。
STEP 5 — 實作

登入 API

import secrets from fastapi import HTTPException # 假資料。下午會換成 SQLite，現在先讓流程跑起來 USERS = {"jase": {"password": "1234", "name": "王小明", "dept": "資訊管理系"}} TOKENS = {} # token → username @app.post("/api/login") def login(data: LoginIn): user = USERS.get(data.username) if not user or user["password"] != data.password: raise HTTPException(status_code=401, detail="帳號或密碼錯誤") token = secrets.token_hex(16) # 發一張隨機通行證 TOKENS[token] = data.username return {"token": token}
CONCEPT — 為什麼要發 token

通行證，不是密碼

❌ 如果每次都送密碼危險密碼要存在瀏覽器裡
每次請求都在網路上跑一遍
被攔截一次就全毀
✓ 發一張 token安全得多密碼只在登入時出現一次
token 可以設定有效期
外洩了就把它作廢，密碼不用改
我們今天做的是簡化版。真實系統會用 JWT、加上過期時間、密碼要用 bcrypt 雜湊後才存 —— 這些是你下一步要學的。

STEP 6 — 前端呼叫後端

fetch：這就是那座橋

// web/login.js f.onsubmit = async (e) => { e.preventDefault(); // 不要讓表單重整頁面 const res = await fetch("http://127.0.0.1:8000/api/login", { method: "POST", // ← 上午講的方法 headers: { "Content-Type": "application/json" }, // ← 標頭 body: JSON.stringify({ // ← Body username: f.username.value, password: f.password.value }) }); if (!res.ok) { msg.textContent = "登入失敗"; return; } // ← 401 const data = await res.json(); localStorage.setItem("token", data.token); // 收好通行證 location.href = "profile.html"; };
ERROR — 預期中的第一個障礙

按下登入，然後爆炸了

// 瀏覽器 Console（F12）會出現這段 Access to fetch at 'http://127.0.0.1:8000/api/login' from origin 'http://127.0.0.1:5500' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
  • 前端在 5500，後端在 8000 —— 瀏覽器認定這是兩個不同的「來源」
  • 同源政策：網頁預設不能跟別的來源要資料否則惡意網站可以偷偷用你的身分去打別人的 API
注意：這是瀏覽器擋的，不是你的後端壞了。用 curl 打同一支 API 會成功 —— 因為 curl 不是瀏覽器。
FIX — 後端明確允許

解決 CORS

# main.py 最上面加這段 from fastapi.middleware.cors import CORSMiddleware app.add_middleware( CORSMiddleware, allow_origins=["http://127.0.0.1:5500"], # 只允許我的前端 allow_methods=["*"], allow_headers=["*"], )
千萬不要寫 allow_origins=["*"] 就上線。那等於對全世界的網站說「歡迎拿我的資料」。開發時圖方便可以，正式環境一定要列清楚。
STEP 7 — 需要憑證才能進

/api/me 的規格

情況請求回應
正常帶 Authorization: Bearer <token>200 · 個人資料 JSON
沒帶沒有 Authorization 標頭401 · 請先登入
亂帶token 不在名單上401 · 請先登入
這就是上午說的「後端才是守門人」。前端可以自己跳到 profile.html，但沒有有效 token，它一筆資料也拿不到。
STEP 7 — 實作

受保護的 API

from fastapi import Header @app.get("/api/me") def me(authorization: str = Header(default="")): token = authorization.replace("Bearer ", "") # 取出通行證 username = TOKENS.get(token) if not username: # 沒有、或不認得 raise HTTPException(status_code=401, detail="請先登入") u = USERS[username] return {"username": username, "name": u["name"], "dept": u["dept"]} # 注意：沒有回傳 password。永遠不要回傳密碼。

DEBUG — 卡住時先查這張表

常見錯誤對照

你看到的真正的原因怎麼修
Address already in use上一個伺服器還在跑回原終端機 Ctrl+C
CORS policy blocked後端沒允許前端的來源加 CORSMiddleware
422 Unprocessable送出的 JSON 少欄位或型別錯看回應裡的欄位名
401 Unauthorized沒帶 token，或 token 不對F12 → Network 看標頭
500 Internal Error後端程式自己爆了看 uvicorn 終端機的紅字
畫面空白沒錯誤JS 出錯但沒人接住F12 → Console
除錯的順序永遠是：Console → Network → 後端終端機。不要用猜的。
UPGRADE — 把假資料換成真的

從 dict 換成 SQLite

import sqlite3 def get_user(username): con = sqlite3.connect("app.db") con.row_factory = sqlite3.Row row = con.execute( "SELECT * FROM users WHERE username = ?", (username,) # ← 用 ? 不要用字串相加 ).fetchone() con.close() return dict(row) if row else None # login 裡只要把 USERS.get(...) 換成 get_user(...) # API 的規格、前端的程式碼，一行都不用改 ← 這就是分層的價值
那個 ? 很重要。如果用字串把使用者輸入接進 SQL，就是 SQL 注入漏洞 —— 下午請 AI 測試時，我們會專門測這一項。

04

網際網路與發佈網站

把「在我電腦上會動」變成「全世界都打得開」。

PART 2 · 30 MIN
CONCEPT — 你打了一整天的那個網址

localhost 到底是什麼

127.0.0.1「我自己」每台電腦都有這個位址，指的都是它自己。你的和我的不是同一台。
localhost127.0.0.1 的小名作業系統內建的對照，不需要查 DNS。
封包去哪了根本沒出門資料在你的網卡裡繞一圈就回來了，完全沒上網路。
所以「我的網站做好了」目前只對你成立。它現在只活在這台筆電裡。
EXPERIMENT — 現場做

讓隔壁同學連到你的網站

# 1. 查出你在這間教室的 IP ipconfig getifaddr en0 # macOS ipconfig # Windows，找 IPv4 位址 # 假設拿到 192.168.1.37 # 2. 讓伺服器聽所有網卡，而不是只聽自己 uvicorn main:app --host 0.0.0.0 --port 8000 # 3. 請隔壁同學在瀏覽器打 # http://192.168.1.37:8000/docs ← 用你的 IP，不是 localhost
成功了嗎？那你已經完成了一次最小的「發佈」—— 只是聽眾僅限這間教室的網路。
CONCEPT — 網址的解剖

Domain · DNS · IP · Port

https:// api.myapp.com : 443 /profile └──┬──┘ └─────┬──────┘ └─┬─┘ └──┬───┘ 協定 網域名稱 Port 路徑 ↓ 交給 DNS 查 203.0.113.45 ← 真正要連的地址
  • 網域名稱是給人記的，電腦只認 IPDNS 就是那本電話簿，全世界共用
  • http 預設 80、https 預設 443所以網址上通常看不到 port —— 用預設值就不用寫
CONCEPT — 網址列那個鎖頭

HTTP 與 HTTPS

HTTPS 保護什麼傳輸過程咖啡廳 Wi-Fi 上的其他人看不到你送出的密碼
中途沒有人能偷改內容
你連到的確實是那個網域
HTTPS 不保護什麼對方是好人詐騙網站也能申請憑證
有鎖頭 ≠ 可以信任這個網站
資料存到對方手上之後就管不著了
今天的部署平台會自動幫你配置憑證。但你要知道那件事真的有發生，不是網址前面多幾個字而已。
BEFORE DEPLOY — 別把鑰匙上傳到 GitHub

環境變數與秘密

# ❌ 絕對不要這樣寫，然後 push 上去 SECRET_KEY = "my-super-secret-1234" # ✓ 從環境變數讀，程式碼裡不留值 import os SECRET_KEY = os.environ.get("SECRET_KEY", "dev-only") # .gitignore 一定要有這幾行 .venv/ .env *.db
GitHub 上的秘密會被機器人在幾分鐘內掃到。已經推上去的話，改密碼比刪 commit 重要得多。

DEPLOY — 一起做

把它送上線

CHECKLIST — 上線後逐項確認

發佈後檢查清單

  • 用手機的行動網路打開不要用教室 Wi-Fi —— 那不算真的對外
  • 網址列有鎖頭沒有的話憑證沒設定好
  • 登入流程完整走一次正確帳密、錯誤帳密都要試
  • 直接打 /profile.html 會被踢回登入頁這是在驗證你的守門有沒有效
  • GitHub 上沒有密碼、金鑰、.env翻一遍 commit 紀錄
  • allow_origins 沒有留著 "*"最常見的上線疏漏

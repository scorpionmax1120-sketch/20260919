# 除錯對照表

## 除錯的順序（永遠先做這個）

1. 瀏覽器 **Console**（F12）── 前端的錯
2. 瀏覽器 **Network** ── 請求真的送出去了嗎？標頭對嗎？狀態碼幾號？
3. **後端終端機** ── uvicorn 的紅字

**不要用猜的。** 先看狀態碼再決定往哪裡找。

## 狀態碼開頭的意思

| 開頭 | 意思 | 往哪裡找 |
| --- | --- | --- |
| 2xx | 成功 | 沒事 |
| 3xx | 轉址 | 通常不用管 |
| 4xx | **你（前端）錯了** | 檢查你送出的請求 |
| 5xx | **後端錯了** | 看伺服器的錯誤日誌 |

## 常見錯誤

| 你看到的 | 真正的原因 | 怎麼修 |
| --- | --- | --- |
| `Address already in use` | 上一個伺服器還在跑 | 回原終端機按 `Ctrl+C` |
| `ModuleNotFoundError: fastapi` | 沒裝套件，或裝到系統 Python | 確認 `(.venv)` 有出現，再 `pip install` |
| `command not found: python3` | 沒裝，或 Windows 沒勾 PATH | 重跑安裝程式，勾 Add to PATH |
| CORS policy blocked | 後端沒允許前端的來源 | 加 `CORSMiddleware` |
| `422 Unprocessable` | 送出的 JSON 少欄位或型別錯 | 看回應裡指出的欄位名 |
| `401 Unauthorized` | 沒帶 token，或 token 不對 | F12 → Network 看請求標頭 |
| `500 Internal Error` | 後端程式自己爆了 | 看 uvicorn 終端機的紅字 |
| 畫面空白、沒有錯誤 | JS 出錯但沒人接住 | F12 → Console |
| **某個欄位一直沒更新，也沒錯誤** | id 撞到瀏覽器內建屬性（最常見的是 `name`） | 改用 `document.getElementById("name")` |
| 前端一直 404 | 用 `file://` 開的，不是 Live Server | 右下角按 Go Live |
| `UnicodeEncodeError` 在標頭 | HTTP 標頭放了中文 | 標頭只能放 ASCII |

## CORS 錯誤長這樣

```
Access to fetch at 'http://127.0.0.1:8000/api/login'
from origin 'http://127.0.0.1:5500' has been blocked
by CORS policy: No 'Access-Control-Allow-Origin' header
is present on the requested resource.
```

**這是瀏覽器擋的，不是你的後端壞了。** 用 `curl` 打同一支 API 會成功 —— 因為 curl 不是瀏覽器。

解法在後端：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:5500"],   # 不要寫 "*"
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 最陰險的一種錯：靜默失敗

```javascript
// ❌ 不會報錯，但畫面永遠不更新
name.textContent = me.name;

// ✓ 正確
document.getElementById("name").textContent = me.name;
```

`window.name` 是瀏覽器**內建的字串屬性**，`<dd id="name">` 蓋不過它。
寫進去不會拋錯、Console 一片安靜，欄位就一直停在「載入中…」。

**教訓：不要依賴「id 會自動變成全域變數」這件事**，一律用 `document.getElementById()`。
有內建同名屬性的 id 還有 `top`、`self`、`length`、`status`、`origin` 等等。
